# Настройка облачной синхронизации «Дневник» (Supabase)

Этот файл — памятка для настройки синхронизации между устройствами.
Приложение (`index.html`) уже содержит весь необходимый клиентский код.
Осталось создать проект Supabase, таблицу и вписать 2 значения в `index.html`.

Синхронизируются: питание/фитнес, съеденные блюда, финансы, привычки,
отметки в списке покупок и тема оформления.

---

## Шаг 1. Создайте проект Supabase

1. Зарегистрируйтесь на https://supabase.com и создайте новый проект (New Project).
2. Дождитесь окончания инициализации БД.
3. Откройте **Project Settings → API** и скопируйте два значения:
   - **Project URL** — вида `https://xxxxxxxxxxxx.supabase.co`
   - **anon public key** — длинная строка, начинающаяся с `eyJ...`

> `anon`-ключ предназначен для использования на клиенте (он публичный).
> Никогда не используйте здесь `service_role`-ключ — он даёт полный доступ к БД.

---

## Шаг 2. Создайте таблицу и включите Realtime

Откройте **SQL Editor → New query**, вставьте и выполните:

```sql
-- Таблица для хранения состояния приложения по ключу синхронизации.
-- ВАЖНО: sync_key должен быть PRIMARY KEY, иначе upsert() будет
-- создавать дубликаты строк при каждом сохранении.
create table if not exists public.user_data (
  sync_key text primary key,
  payload jsonb,
  updated_at timestamptz default now()
);

-- Включаем Row Level Security (обязательно для публичных таблиц).
alter table public.user_data enable row level security;

-- Разрешаем анонимному клиенту читать/писать.
-- Это осознанный компромисс для личного проекта: единственная защита —
-- секретность значения sync_key (см. «Безопасность» ниже).
drop policy if exists "anon_all" on public.user_data;
create policy "anon_all" on public.user_data
  for all
  to anon
  using (true)
  with check (true);

-- Подключаем таблицу к Realtime, чтобы устройства получали обновления «онлайн».
alter publication supabase_realtime add table public.user_data;
```

Проверка: в **Table Editor** должна появиться таблица `public.user_data`
с колонками `sync_key`, `payload`, `updated_at`.

---

## Шаг 3. Впишите ключи в index.html

Откройте `index.html`, найдите в самом начале тега `<script>` блок:

```js
/* ================= НАСТРОЙКИ ОБЛАКА (SUPABASE) ================= */
const SUPABASE_URL = "ВСТАВЬТЕ_СЮДА_PROJECT_URL";
const SUPABASE_ANON_KEY = "ВСТАВЬТЕ_СЮДА_ANON_KEY";
```

Замените значения на **Project URL** и **anon public key** из Шага 1:

```js
const SUPABASE_URL = "https://xxxxxxxxxxxx.supabase.co";
const SUPABASE_ANON_KEY = "eyJhbGciOi...ваш_длинный_anon_ключ...";
```

## Шаг 4. Проверка работы

1. Откройте приложение в браузере (см. «Важно про запуск» ниже).
2. Нажмите кнопку **☁️ Офлайн** (телефон) или **☁️ Облако: Офлайн** (сайдбар).
3. Введите любое уникальное кодовое слово — это ваш ключ синхронизации.
   Например: `moy-dnevnik-2026`.
4. Статус на кнопке должен смениться: `⏳ Загрузка...` → `☁️ Синхронно`.
   - `🔑 Задайте ключ` — ключ не введён или пустой.
   - `⚠️ Ошибка сети` — см. «Если не работает».
5. Введите **то же самое** кодовое слово на втором устройстве.
6. Измените данные на первом устройстве — через 1–2 секунды они
   появятся на втором (статус мелькнёт `☁️ Запись...` → `☁️ Синхронно`).

Ключ сохраняется в `localStorage` устройства (`lifeOS_sync_key`),
вводить его заново при каждом запуске не нужно.

## Если не работает

| Симптом | Причина | Решение |
|---|---|---|
| `⚠️ Ошибка сети`, в консоли `relation "public.user_data" does not exist` | Таблица не создана | Выполните SQL из Шага 2 |
| `new row violates row-level security policy` | Нет политики доступа | Выполните `create policy` из Шага 2 |
| Ключи не подставлены | Остались плейсхолдеры | Шаг 3 |
| Строки дублируются в таблице | `sync_key` не PRIMARY KEY | Пересоздайте таблицу по SQL из Шага 2 |
| Устройства не синхронизируются «онлайн», но синхронно при перезагрузке | Не включён Realtime | Выполните `alter publication supabase_realtime add table` |
| Ничего не работает при открытии файла с диска (`file://`) | Supabase блокирует CORS | Откройте через http/https |

## Важно про запуск (CORS и `file://`)

Открывать `index.html` двойным щелчком с диска (`file:///...`) **не рекомендуется**:
origin будет `null`, и запросы к Supabase могут блокироваться браузером.
Надёжные варианты:

- **GitHub Pages**: репозиторий уже есть — включите Pages в настройках
  репозитория (Settings → Pages → Deploy from branch → `main` → `/root`).
- Локальный сервер: `python3 -m http.server 8000` и откройте
  `http://localhost:8000/index.html`.

## Безопасность (важно прочитать)

- Политика `anon_all` разрешает **любому** владельцу `anon`-ключа читать и
  писать **все** строки таблицы. `anon`-ключ встроен в HTML и виден любому,
  кто откроет исходный код страницы.
- Единственная защита данных — **секретность значения `sync_key`**:
  зная URL + `anon`-ключ + ваш `sync_key`, можно прочитать ваши данные.
  Выбирайте длинное непредсказуемое кодовое слово и не публикуйте его.
- Для персонального дневника на 3 устройства это приемлемый компромисс.
  Если нужна реальная изоляция пользователей — потребуется Supabase Auth
  (вход по e-mail) и политики на основе `auth.uid()`. Это отдельная задача,
  выходящая за рамки текущей настройки.

## Что именно добавлено в index.html (для справки)

1. Подключение SDK Supabase (`<script src="...@supabase/supabase-js@2">`).
2. Кнопки статуса: `#mobile-cloud-btn` в хедере, `#desktop-cloud-btn` в сайдбаре.
3. Блок синхронизации в начале основного `<script>`:
   `updateCloudUI`, `promptSyncKey`, `getAppStatePayload`, `applyAppStatePayload`,
   `pushChangesToCloud`, `initCloudSync`.
4. Вызовы `pushChangesToCloud()` после изменений: финансы, привычки,
   съеденные блюда, список покупок, число персон, тема, пересчёт нормы питания.
5. Запуск `initCloudSync()` в конце `window.onload`.

Таблица в Supabase: `public.user_data(sync_key text primary key, payload jsonb, updated_at timestamptz)`.
